# Node Trades Rebuild — GoldRush Parity Fallback

## What this is

A small pipeline that rebuilds 1m OHLCV candles directly from **official
Hyperliquid node_trades archives**, for the specific symbol/time windows
where GoldRush HyperCore candles diverge from the official
`hl_candleSnapshot` feed by a few price ticks and local reconciliation
(alignment, timezone, parsing, 1m→Nm rollup) cannot explain the delta.

This is the `node_trades_reconstruction` fallback embedded in the GoldRush
support package (`data/research/goldrush_support_package_latest.json` →
`node_trades_reconstruction`, generated by
`src/data/candle_providers/parity_secondary.py`). It exists **because the
GoldRush parity gate is not being relaxed** — instead of loosening
tolerance or patching GoldRush data locally, we source a second,
official-only candle series for the disputed windows and validate against
that.

Pipeline steps (see `src/data/candle_providers/node_trades_rebuild.py`):

1. Read the divergent windows out of a GoldRush support package.
2. Enumerate the S3 archive objects needed to cover those windows.
3. Fetch each object via a pluggable fetcher (real S3, or a fake for tests).
4. Parse trade records (tolerant of the `node_trades` / `node_fills` JSON
   shapes; LZ4-decompresses if the optional `lz4` package is installed).
5. Aggregate trades into 1m OHLCV bars using HL bucket boundaries
   (`t`/`T` semantics) and the existing dynamic-quantum/`format_hl_price`
   helpers in `tick_meta.py` — no new rounding logic is introduced.
6. Upsert into the research DB with `source=hl_node_trades_rebuild`,
   **never** overwriting protected official rows (`hl_candleSnapshot`,
   `hl_trades_ws`, `hl_ws_1m_tape_agg`).
7. Invoke an optional re-validation hook with the rebuilt rows so a caller
   can immediately re-run secondary validation on just that window.

## Prerequisites for a real rebuild

- An AWS account, since Hyperliquid's historical archives are published to
  **requester-pays** S3 buckets — you pay the data-transfer cost, not HL.
- `pip install boto3` (optional dependency; not installed by default so the
  rest of the module tree imports cleanly without it).
- AWS credentials configured (`aws configure`, environment variables, or an
  IAM role) with S3 read + requester-pays permission.
- Optionally `pip install lz4` if the fetched archive objects are
  LZ4-compressed and you want the parser to auto-decompress them (otherwise
  pre-decompress before calling `parse_archive_object`).

Layout facts (confirmed from official docs, cited in module docstrings):

- `s3://hyperliquid-archive/market_data/[date]/[hour]/[datatype]/[coin].lz4`
  — documented, requester-pays, roughly monthly uploads, "no guarantee of
  timely updates."
- `s3://hl-mainnet-node-data/node_trades` (older/raw trade format) and
  `node_fills` / `node_fills_by_block` (API-aligned fill format) — the
  node-level trade archive bucket. Its exact date/hour key partitioning is
  **not** pinned down in the docs the way `market_data` is, so this module
  treats the key template as **configurable** (`DEFAULT_KEY_TEMPLATE` in
  `node_trades_fetcher.py`) rather than hardcoding it — pass your own
  `key_template`/`bucket` if HL's actual layout differs.

## Usage

Dry run (default — no network access, ever):

```bash
python scripts/hl_node_trades_rebuild.py \
  --package data/research/goldrush_support_package_latest.json \
  --symbols BTC,ETH
```

Prints the priority windows, the exact S3 object keys required, an object
count, and the access requirements (AWS credentials, `boto3`, requester-pays
cost warning).

Real download + rebuild (requires `boto3` + AWS credentials):

```bash
python scripts/hl_node_trades_rebuild.py \
  --package data/research/goldrush_support_package_latest.json \
  --symbols BTC,ETH \
  --db data/research/hyperliquid.db \
  --execute
```

## What this does *not* change

- The GoldRush parity gate (`src/data/candle_providers/parity.py`) and its
  dynamic 5-sig-fig-quantum tolerance are untouched.
- `hl_candleSnapshot` (and other protected official sources) rows are never
  overwritten by rebuilt data — `save_research_candles_non_destructive`
  skips them, and the integration test asserts this explicitly.
- Rebuilt `hl_node_trades_rebuild` data is **not** automatically treated as
  validated. OOS dataset readiness and hyperparameter tuning stay blocked
  on the disputed windows until the rebuilt candles pass their own
  secondary validation (`run_secondary_validation` in
  `parity_secondary.py`) — this pipeline produces the input for that
  re-validation, it does not mark the gate satisfied itself.
